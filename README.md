# R&D-модель для ШІ-асистента лікаря-психолога

Цей репозиторій містить дослідницьку Python-модель для проєктування,
симуляції та оцінювання контурів зворотного зв'язку, які можуть бути
використані під час розроблення ШІ-асистента лікаря-психолога. Проєкт не є
готовим клінічним застосунком і не виконує самостійної діагностики. Його
призначення - надати програмно-експериментальну основу для аналізу того, як
керовані політики, метрики ризику, новизни, різноманітності та стійкості
поведінки системи можуть підтримувати безпечну логіку психоемоційного
скринінгу.

Репозиторій розглядається в контексті науково-дослідної роботи за договором
№ 431 від 10.06.2026 «Розроблення дослідного зразка експертної системи з
елементами штучного інтелекту для психоемоційного скринінгу» - ШІ-асистент
для психолога. У цьому контексті кодова база слугує R&D-шаром для перевірки
підходів до керування взаємодією, маршрутизації користувача, стабілізації
рішень і порівняння різних стратегій регулювання.

## Призначення

Основна ідея проєкту полягає у моделюванні системи, яка працює ітераційно:
отримує вимірювані показники поточного стану, порівнює їх із цільовими
значеннями та коригує параметр керування. У поточній реалізації це описано як
симулятор керованого виробництва знань, однак та сама кібернетична логіка
може бути використана як дослідницька модель для ШІ-асистента лікаря-психолога.

У прикладному медико-психологічному сценарії така модель допомагає аналізувати:

- як підтримувати баланс між глибиною скринінгу та безпечним обмеженням
  автоматизованої інтерпретації;
- як виявляти ситуації, що потребують ескалації до профільного фахівця;
- як порівнювати різні політики керування взаємодією;
- як оцінювати стійкість системи за умов зміни навантаження або появи
  критичних ознак;
- як формувати основу для майбутньої персоналізованої маршрутизації пацієнтів.

## Клінічний контекст

ШІ-асистент лікаря-психолога розглядається як складова дослідного зразка
гібридної експертної системи для психоемоційного скринінгу. Його роль полягає
не у заміні клінічного рішення, а у підтримці структурованого збору інформації,
первинної стратифікації ризиків, виявлення «червоних прапорців» і підготовки
інформаційного висновку для фахівця.

У межах предметної області враховуються стандартизовані опитувальники та
скринінгові модулі:

- `PHQ-9` - оцінювання депресивних симптомів;
- `GAD-7` - оцінювання тривожних симптомів;
- `PQ-16` - попереднє виявлення ризику психотичних розладів;
- `MDQ` - скринінг симптомів маніакального та біполярного спектра;
- `CFQ` - оцінювання суб'єктивних когнітивних труднощів;
- `MoCA` - оцінювання когнітивних порушень, лише лікарем або під його
  безпосереднім контролем;
- `AUDIT-C` - виявлення ризиків, пов'язаних із вживанням алкоголю;
- `DAST` - виявлення ризиків, пов'язаних із вживанням інших психоактивних
  речовин.

Для кожного такого модуля в межах цільової експертної системи мають бути
визначені роль асистента, послідовність взаємодії, правила фіксації та
перевірки відповідей, межі інтерпретації результатів, умови ескалації та
формат представлення висновку лікарю-психологу.

## Базовий алгоритм дистанційного скринінгу

Окремим прикладним орієнтиром є базовий алгоритм первинного психіатричного
скринінгу для дистанційної допомоги. У контексті майбутнього ШІ-асистента він
має підтримувати послідовну логіку:

1. Перевірити умови безпечного дистанційного контакту.
2. Виявити безпосередні загрози життю та здоров'ю.
3. Перевірити медичні, органічні та поведінкові «червоні прапорці».
4. Оцінити основні групи психічних симптомів.
5. Визначити ступінь порушення повсякденного функціонування.
6. Обрати подальший спеціалізований модуль або маршрут до фахівця.

Система не встановлює психіатричного діагнозу, не призначає лікування, не
замінює клінічне інтерв'ю, огляд лікаря або невідкладну медичну допомогу.

## Як поточний симулятор підтримує цей контекст

Поточна кодова база реалізує симулятор із керованим параметром `pi`, який
впливає на частку дослідницьких або пошукових дій у кожному циклі. Стан
системи описується через історію метрик:

- `N` - частка нових виявлень або новизни в циклі;
- `D` - різноманітність залучених тем або напрямів;
- `pi` - керувальний параметр політики;
- `T_insight` - час до появи визначеної цільової події.

У контексті ШІ-асистента ці змінні варто трактувати як абстрактну модель, а не
як готові клінічні шкали. Вони дають змогу досліджувати, як система може
регулювати глибину взаємодії, підтримувати різноманітність перевірених
клінічних напрямів, реагувати на зміну умов і не виходити за межі безпечної
автоматизації.

Доступні сценарії політик:

- `impact_only` - мінімізація пошуку нових напрямів;
- `no_control` - фіксована низька інтенсивність керування;
- `random` - максимально випадкова дослідницька поведінка;
- `pid` - пропорційно-інтегрально-диференційне керування;
- `lqr` - лінійно-квадратичне регулювання;
- `cpg` - адаптивна політика із функцією винагороди та штрафом за недостатню
  різноманітність.

## Архітектура репозиторію

```text
src/
  cli.py                 Командний інтерфейс запуску, зведення та побудови графіків
  sim/
    core.py              Ядро симуляції, конфігурація та стан
    policies.py          Вибір політик керування
  controllers/
    pid.py               PID-контролер
    lqr.py               LQR-контролер
    cpg.py               Адаптивна CPG-політика
  analysis/
    summaries.py         Зведення результатів у CSV
    plots.py             Побудова прикладних графіків
  data/
    openalex_seed.py     Допоміжні засоби для зовнішніх джерел
    crossref_utils.py    Допоміжні засоби для Crossref

config/
  main.yaml              Основна конфігурація експерименту
tests/                   Pytest-тести
docs/                    Технічні нотатки та документація
results/                 JSON-результати запусків
reports/                 CSV-звіти та графіки
```

## Встановлення

Потрібен Python 3.10 або новіший.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Для Windows PowerShell активація середовища зазвичай має вигляд:

```powershell
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Для розроблення та запуску тестів додатково встановіть dev-залежності:

```bash
pip install -r requirements-dev.txt
```

## Запуск симуляцій

Запуск усіх сценаріїв із типовою конфігурацією:

```bash
python -m src.cli run --config config/main.yaml --scenario all --trials 50
```

Запуск окремого сценарію:

```bash
python -m src.cli run --config config/main.yaml --scenario pid --trials 10
```

Підтримуються сценарії:

```text
impact_only, no_control, random, pid, lqr, cpg
```

## Зведення та візуалізація результатів

Після запуску симуляцій результати зберігаються у `results/` як JSON-файли за
сценаріями. Для побудови CSV-зведення:

```bash
python -m src.cli summarize --results results --out reports/summary.csv
```

Для побудови прикладних графіків:

```bash
python -m src.cli plot --results results --out reports/figures
```

CSV-звіт містить сценарій, номер випробування, час до цільової події,
середню новизну та середню різноманітність.

## Docker Compose

За потреби можна запускати проєкт у контейнері:

```bash
cp .env.example .env
docker compose up --build simulator
docker compose run --rm summarize
docker compose run --rm plot
```

Каталоги `config/`, `results/`, `reports/` і `data/` монтуються в контейнер.
Параметри `SCENARIO` та `TRIALS` можна змінити у файлі `.env`.

## Конфігурація експерименту

Основні параметри розміщено у `config/main.yaml`:

- `seed` - початкове зерно генератора випадкових чисел;
- `horizon` - кількість циклів симуляції;
- `topics` - кількість тематичних вузлів;
- `outputs_per_cycle` - кількість виходів або дій за цикл;
- `breakthrough` - пара тем, що позначає цільову подію;
- `noise_novelty` - шум вимірювання новизни;
- `shock` - параметри зміни умов після заданого циклу;
- `targets.novelty` - цільове значення новизни;
- `pid`, `lqr`, `cpg` - параметри відповідних політик керування.

Для дослідження логіки майбутнього ШІ-асистента ці параметри можна
інтерпретувати як керовані умови експерименту: цільові рівні обережності,
інтенсивність уточнень, стійкість до зміни навантаження та вимоги до
різноманітності перевірених напрямів.

## Тести

Запуск тестів:

```bash
python -m pytest
```

Тести перевіряють базовий цикл симуляції, роботу PID-контролера та CLI-сценарій
із запуском і зведенням результатів.

## Межі застосування

Цей репозиторій є дослідницькою та інженерною основою. Він може бути корисним
для розроблення, тестування та документування принципів керованої взаємодії в
ШІ-асистенті лікаря-психолога, але сам по собі не є медичним виробом,
діагностичною системою або сервісом невідкладної допомоги.

Будь-яке практичне використання в клінічному або консультативному середовищі
потребує окремої валідації, експертного клінічного нагляду, етичного аналізу,
захисту персональних даних і відповідності чинним нормативним вимогам.

## Публікації та апробація

Контекст НДР і пов'язані результати апробовано у наукових матеріалах щодо
мультимодальних онтологій, цифрових двійників людини, безпечної генерації для
українського клінічного асистента та edge-обчислень для локального inference.
